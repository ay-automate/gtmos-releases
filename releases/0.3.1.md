# GTM OS 0.3.1

CLI: `@gtmos/cli` 0.3.1. Images: `ghcr.io/ay-automate/gtmos-{api,worker,mcp,console}:0.3.1` (also tagged `stable` once the stable channel moves), plus `pgvector/pgvector:pg16`.

0.3.1 is a patch release driven by a real, live setup of a brand on 0.3.0. It makes setup honest and short for one
person, makes the approval and agent rules clearer and safer, lets agents do much more through MCP while keeping
the very risky actions with people, and fixes the gaps the live test found in integrations, packages, the setup
wizard, scoring and the console.

The catalog is now 962 operations (430 Q, 360 D, 5 T, 33 E, 134 M).

## Before you upgrade

- **Agents now run three checks directly.** `connections.test`, `connections.preflight` and `crm.sync` run directly
  with a granted agent key (limited per minute, per day and per organization). Before, an agent key got a proposal.
  Send `mode: "propose"` to keep the old behaviour. With Dry Mode on, an agent `crm.sync` still becomes a proposal.
- **An agent never stores a key you paste in chat.** An agent that calls `connections.create` or
  `connections.rotate` now gets a request for a person to type the key (`connections.request_secret`). A person enters
  it in the console.
- **Live email lanes need a postal address.** On a live instance a lane that sends email without a postal address now
  has its applies and sends refused. Existing lanes are not paused, but their sends are refused until you add the
  address.
- **Scores from the stock model are provisional.** They are capped below qualified and never drive seeds, enrichment
  order or outreach. New organizations score only with a signed model (strict mode). On an existing organization,
  an owner can run the one-time rescore.
- **The Workbench tab of the Score engine moved.** Anyone who had hidden the old tab sees it again.
- **A step-up factor exists, and it is off by default.** An owner can set up an authenticator for sensitive grants. It
  needs its own key (`GTMOS_STEPUP_KEY`) and an email transport. Grants for agents stay off. See
  step-up factor.
- **Setup is solo by default.** `gtm setup` asks for no second approver; `--team` opts in. The `.env` guard is a
  guard, not a guarantee, and it does NOT stop `gtm login --instance`.
- **Transcripts from Gong need the Gong pack.** `transcripts.sync` no longer reads Gong unless the Gong pack is installed, and then it reads only the installer's own data.
- **BigQuery pack version 2 needs a project id.** Installs of version 1 keep validating but show "install the pack again".
- **Embeddings are not retried.** Once a record's text is sent to an embedding provider, the job is not retried by
  itself; an explicit `search.reindex_now` re-runs it.

## What is new

- **One person can finish setup.** No approver account is needed; the console, the CLI and MCP all say who approves
  and why.
- **Agents can do more.** Agents can lower spend caps, turn Dry Mode on, read needs through their key, propose
  removing a failed connection, ask a person for a secret through a one-time link, and leave "Needs a human" items.
  Raising a cap, turning Dry Mode off, signing, approving and running customer-facing actions stay with people.
- **Honest connections.** Failed attempts can be retried or removed, links to connect an app finish in the console,
  and read-only access can be granted per app.
- **Go live signing.** Applying a change proposes its definitions for signing in one step.
- **Packages and approvals.** Bulk enable and promote, a clearer approval card with a risk reason, and approve-all for
  matching items.
- **Setup wizard.** It shows only what is really in place, lets you add your own apps and markets, and refuses to
  count an agent's draft as done.
- **Score and outreach.** A new Score cockpit with reasons, tiers, an accounts-to-create tab, next best move and
  feedback reason codes; read-only outreach cockpit operations; LinkedIn engagers and AI visibility on the account.
- **Console.** Engine cards collapse, cards in a row share one height, every page scrolls, and Integrations is easier
  to find.
- **Motions.** Offers, competitors and definitions as proposals, lane senders with daily caps, and page readiness in
  SEO.

## Known limits

- **No live check against real app accounts.** Everything was tested against fake providers.
- **Envelope grants for agents stay off.** The owner-signed envelope has its tables and card, but nothing enforces it
  yet; the next steps need this release published first. The authenticator for passkeys is not built.
- **Environment-limited and per-kind agent key presets** cannot be expressed yet.
- **Planned for 0.3.2:** moving the owner password out of `.env`, holding the re-index spend under Dry Mode, the
  other messaging channels through the messaging add-on (WhatsApp and email through it first), the remaining
  Ads and SEO/GEO refinements, and a review of the Gong, Calendly, BigQuery and Snowflake scoping changes.
- **A few browser walks were not run before this note**.

## Upgrade

An upgrade never touches, removes or loses your data. Every migration only adds, the updater takes a verified backup first, and a failed upgrade rolls back by swapping the images.

0.3.1 is reached **from 0.3.0**. It needs `@gtmos/cli` 0.3.1 or newer.

1. **Upgrade the CLI first.**

   ```bash
   npm i -g @gtmos/cli@latest
   ```

2. **See what is available.** This changes nothing.

   ```bash
   gtm upgrade --check
   ```

3. **Rehearse, then upgrade.** Run from your instance folder, or pass `--dir <path>`.

   ```bash
   gtm upgrade --to 0.3.1 --dry-run
   gtm upgrade --to 0.3.1
   ```

If anything fails, `gtm upgrade --rollback 0.3.0` swaps the images back; the database is never restored. Read "Before you upgrade" above first.
