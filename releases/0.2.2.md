# GTM OS v0.2.2

CLI: `@gtmos/cli` 0.2.4 (images are pulled from the public registry `ghcr.io/ay-automate` by default; the npm package now ships only the minified build).

The stabilization release: everything that exists works in live mode, end to end, driven by Claude Code (or any MCP agent) from an empty folder.

## Install

```bash
npm i -g @gtmos/cli
mkdir my-gtm && cd my-gtm
gtm init            # writes CLAUDE.md, AGENTS.md, .mcp.json, skills, docs/gtmos
claude              # restart Claude Code here, then run /setup-gtmos
```

Manual path: `gtm setup ./instance --org Acme --email you@x.com --approver-email ops@x.com --version 0.2.2`, then `gtm doctor --strict`.

Images: `ghcr.io/ay-automate/gtmos-{api,worker,mcp,console}:0.2.2` (also tagged `stable`), plus `pgvector/pgvector:pg16`.

## Highlights

- **Claude-driven setup.** `gtm init` from an empty folder + the `/setup-gtmos` runbook: Claude installs, configures and builds the GTM system, and asks you only for what it cannot do (OAuth consent, approver sign-in, keys you keep private). `CLAUDE.md` at the project root.
- **Agent parity.** An owner/admin's agent key can do every setup and configuration operation over MCP, scoped and audited. Agents never approve, execute, self-escalate, give OAuth consent or toggle Dry Mode.
- **Connections, OAuth first.** One Connections list (Integrations > Connections) with the best connect method per integration. Composio in all three modes (OAuth "Connect Composio", `ck_` Connect key, `ak_` project key), discovery and sync of already-connected apps, any CRM through Composio, Gmail / Outlook / Google Calendar / Slack / GA4 / Search Console via Composio.
- **Go live.** Environments > Go live card: review and sign all definitions, promote dev to prod under one approval (`env.promote`, `definition.sign_many`, `config.promotion_status`; CLI `gtm definition sign-all`, `gtm promote --all`).
- **Four-eyes everywhere.** The proposer, and the human an agent acts for, can never approve or execute; they can withdraw (veto). Org-wide Dry Mode switch in Settings > Safety.
- **Honest readiness.** Live credential checks (Composio, looot, mailboxes), blueprint requirements that follow enabled packages and environments.
- **Outreach.** Native and Composio sending mailboxes, default play bound to the org's email lane on blueprint apply.
- **CLI fixes.** `gtm token create/list`, `.env` quoting, workspace instance fallback, bundled baseline manifests, no literal agent key in `.mcp.json`.

## Known limits

- Blueprint package signatures do not yet cover `blueprint.yaml`.
- Installing the CLI without `-g` (project-local / `npx`) can fail to load the generated Prisma client: use `npm i -g`.
- Node prints a DEP0040 (`punycode`) deprecation warning; harmless.
